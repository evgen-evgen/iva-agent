# Полный запуск Ивы: Telegram, LibreChat, Mail и Plaud

Инструкция для одной установки Ивы с CEO-памятью, Telegram-ботом, браузерным
интерфейсом LibreChat, почтой через IMAP/SMTP, импортом встреч Plaud,
PostgreSQL для метаданных и Garage для S3-архива.

Для рыночного пилота устанавливаем нашу CEO-сборку из отдельного репозитория,
фиксируя проверенный коммит или тег. Публичная версия `smixs/iva-agent/main`
не является источником этой установки: наши изменения могут ещё отсутствовать в ней.
Развитие и обновление CEO-сборки ведём отдельно; решение об объединении с основной
Ивой принимаем после обратной связи от пользователей пилота.

Для уже настроенного CEO checkout см. [запуск и перезапуск нашей установки](ceo-operations.md).
Команды ниже для новой одиночной установки; при нескольких экземплярах Ивы
используйте только сервисы нужного checkout.

После запуска Telegram и LibreChat обращаются к одному агенту, используют одну
память, проекты, людей и инструменты. Mail и Plaud подключаются к Иве. Чаты двух
интерфейсов имеют отдельные истории; общая память не означает одну общую переписку.

```text
Telegram-бот → Telegram bridge ─┐
                              ├→ Ива → CEO vault: проекты, люди, встречи, обязательства
LibreChat → API Ивы /v1 ───────┘    ├→ Mail MCP → IMAP/SMTP
                                   ├→ Plaud MCP → разбор встреч → CEO vault
                                   └→ PostgreSQL (очередь) + Garage S3 (тексты и разборы)
```

Основной путь ниже — постоянно работающий Linux-сервер с systemd user services и
Docker Compose для LibreChat. Достаточно одного запущенного агента Ивы: не запускайте
рядом второй `npm run start:ui` на том же порту, если агент уже работает как сервис.

## 1. Подготовить сервер и доступы

Понадобятся:

- Обычный пользователь Linux с возможностью установить системные пакеты; SSH-доступ.
- Рабочий провайдер модели для Ивы. Его настраивает мастер установки.
- Telegram-бот от [BotFather](https://t.me/BotFather), токен и аккаунт CEO для allowlist.
- Почтовый ящик: логин, пароль или пароль приложения, адреса IMAP/SMTP и режимы TLS,
  полученные у своего почтового провайдера.
- Аккаунт Plaud с Cloud Sync и хотя бы одной записью с готовым транскриптом для проверки.
- Docker Engine и Docker Compose на сервере, доступные этому пользователю.
- Два разных email для аккаунтов LibreChat: технический администратор и CEO.
- При работе с голосом — настроенный Deepgram. Текстовые чаты его не требуют.

Если Docker ещё не установлен, для Ubuntu используйте
[официальную установку Docker Engine](https://docs.docker.com/engine/install/ubuntu/)
с Compose plugin и настройте доступ пользователя к Docker. Дальнейшие команды
предполагают, что `docker compose` работает из его сессии.

Доступы вводятся в мастер, приватные конфигурационные файлы или браузер авторизации.
Не присылайте пароли и токены в чат. Docker в этом сценарии использует host network,
а веб-интерфейс и MongoDB слушают loopback; для удалённого доступа ниже используется SSH.

## 2. Установить нашу CEO-сборку и настроить Telegram

На чистом сервере под обычным пользователем получите код нашей сборки.
Перед выполнением замените `IVA_CEO_CODE_REF` на проверенный коммит или тег,
который подготовлен для пилота. Номер версии в `package.json` сам по себе
не отличает нашу сборку от публичной; идентификатор коммита обязателен.

```bash
IVA_CEO_CODE_REF="ЗАМЕНИТЬ_НА_ПРОВЕРЕННЫЙ_COMMIT_ИЛИ_ТЕГ"
git clone https://github.com/evgen-evgen/iva-agent.git "$HOME/iva-ceo" || exit 1
cd "$HOME/iva-ceo" || exit 1
git switch -c ceo-pilot "$IVA_CEO_CODE_REF" || exit 1
git remote -v
git rev-parse HEAD
bash ./install.sh
```

Локальный `install.sh` использует этот checkout без переключения на публичный `main`.
Не запускайте вместо него установщик через `curl` из `smixs/iva-agent`.
Если переносите текущую разработку на другой сервер, сначала сохраните нужные
изменения в коммит и предоставьте его в нашем репозитории: незакоммиченные правки
не попадут в `git clone`. Проверенная версия должна включать CEO-профиль,
`scripts/plaud-sync.ts`, `scripts/mail-sync.ts`, `scripts/ingestion-setup.ts`,
`plugins/iva-mail/` и `plugins/iva-plaud/`. Наличие одного Plaud MCP-плагина
в старом ядре не добавляет фоновый импорт.

Требования сервера и описание мастера: [установка](install.md).
Команда скачивания публичной Ивы из той инструкции к CEO-пилоту не относится.

В мастере настройте провайдер и модель, токен Telegram-бота, allowlist CEO, часовую
зону, каталог памяти и профиль `ceo`. Укажите имя CEO, если нужно выделять его
обязательства отдельно. Telegram работает через long polling: публичный webhook
для этого сценария не требуется.

После установки используйте рабочий каталог с `package.json` и `.env`:
в этом сценарии это `$HOME/iva-ceo`.
Дальнейшие команды выполняйте из этого каталога.

```bash
node --version
npm run iva -- status
```

Node.js должен быть версии 24. Ожидаются работающие агент и Telegram bridge.
Если мастер был пропущен или нужно изменить настройки:

```bash
npm run iva -- config
```

Команды через `npm run iva --` используют эту установку, а не случайный глобальный
`iva` от другого экземпляра.

Проверьте или обновите существующие значения в `.env`, не создавая дубликатов:

```dotenv
IVA_MEMORY_PROFILE=ceo
IVA_CEO_NAME=Имя CEO
ASSISTANT_TIMEZONE=Europe/Minsk
TELEGRAM_ENABLED=true
IVA_UPDATE_NOTIFICATIONS_ENABLED=false
IVA_VAULT_BACKUP_BACKEND=garage
```

Часовую зону и имя замените своими. В том же файле должны быть заполнены настройки
Telegram из мастера:

| Настройка                       | Что указать                                                                             |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`            | Токен своего бота                                                                       |
| `TELEGRAM_BOT_USERNAME`         | Username бота, определённый мастером                                                    |
| `TELEGRAM_WEBHOOK_SECRET_TOKEN` | Секрет между локальным bridge и агентом                                                 |
| `TELEGRAM_ALLOWED_USER_IDS`     | Числовой user ID CEO; пустой allowlist не разрешает переписку                           |
| `TELEGRAM_NOTIFICATION_CHAT_ID` | Личный chat ID для напоминаний, дайджестов и обычных уведомлений                        |
| `TELEGRAM_DIAGNOSTIC_CHAT_ID`   | Отдельный системный чат для технических ошибок, health, памяти и предложений обновления |

Бот должен иметь доступ к обоим чатам назначения. Для личного чата сначала начните
разговор с ботом; для системной группы добавьте бота. Chat ID назначения и user ID
allowlist — разные настройки. Если системный чат не задан, соответствующие сообщения
не получают Telegram-адрес назначения.

Примените CEO-схему:

```bash
npm run init-vault
```

Ожидается `CEO profile applied` или `CEO profile already present`. Существующие
карточки сохраняются. Описание переменных: [конфигурация](configuration.md).

### Версия кода и память пилота

Для каждой установки запишите URL репозитория и результат `git rev-parse HEAD`.
Обновления пилота берите только из нашей CEO-сборки после проверки выбранного коммита;
не используйте публичный установщик, `repair.sh` или `iva update` как способ перехода
на основную Иву. Для созданной локальной ветки `ceo-pilot` канал обновления ещё
не настроен: смена версии требует отдельной процедуры выпуска.
Автоматические проверки и Telegram-предложения обновления по умолчанию выключены
в этой сборке (`IVA_UPDATE_NOTIFICATIONS_ENABLED=false`), в том числе при отсутствии
переменной в старой `.env`. Включать их для пилота пока не нужно.

Код и накопленные данные имеют разные жизненные циклы. При обновлении сохраняйте
`.env`, фактические каталоги vault и данных, конфигурацию плагинов, PostgreSQL,
Garage и MongoDB LibreChat. Перед сменой версии делайте резервную копию и проверяйте
совместимость CEO-схемы. Будущее объединение кода возможно, но требует проверки
миграций; перенос на другую версию не должен начинаться с пустой памяти.
Для текущей настроенной установки используйте [CEO operations](ceo-operations.md),
а не повторную установку с нуля.

## 3. Подготовить настройки LibreChat в общей `.env`

Добавьте или обновите:

```dotenv
OPEN_WEBUI_API_KEY=ЗАМЕНИТЬ_СЛУЧАЙНОЙ_СТРОКОЙ
LIBRECHAT_NOTIFICATION_SECRET=ЗАМЕНИТЬ_ДРУГОЙ_СЛУЧАЙНОЙ_СТРОКОЙ
LIBRECHAT_NOTIFICATION_USERS=admin@example.com,ceo@example.com
LIBRECHAT_PORT=3080
LIBRECHAT_MONGO_PORT=27018
LIBRECHAT_PUBLIC_URL=https://libre.example.com
```

Для каждого из двух секретов отдельно выполните:

```bash
openssl rand -hex 32
```

Сохраните результаты в `.env` на сервере. Email замените адресами будущих аккаунтов. `LIBRECHAT_PUBLIC_URL` замените адресом,
который открывается в браузере CEO: он используется кнопкой из Telegram. Для
SSH-туннеля ниже это `http://127.0.0.1:3080`, доступный только при открытом туннеле;
для доступа с телефона нужен доступный ему адрес, например через VPN или HTTPS.
Название `OPEN_WEBUI_API_KEY` используется и для LibreChat: это ключ доступа к API
Ивы, установка Open WebUI для него не нужна. `ASSISTANT_BEARER`, создаваемый установкой
для внутренних клиентов Eve, — отдельный секрет; не заменяйте его этим ключом.

`LIBRECHAT_NOTIFICATION_SECRET` должен совпадать у Ивы и контейнера LibreChat:
оба получают его из этой `.env`. `LIBRECHAT_NOTIFICATION_USERS` разрешает указанным
авторизованным аккаунтам читать колокольчик уведомлений, но не создаёт сами аккаунты.

## 4. Подключить Mail-плагин

Сначала определите настоящий каталог данных этой установки и создайте конфигурацию:

```bash
IVA_RUNTIME_DATA_DIR="$(node --env-file-if-exists=.env --input-type=module -e 'import { dataDir } from "./agent/lib/data-dir.ts"; console.log(dataDir())')"
mkdir -p "$IVA_RUNTIME_DATA_DIR/custom/plugins"
if [ ! -f "$IVA_RUNTIME_DATA_DIR/custom/plugins/iva-mail.env" ]; then
  cp plugins/iva-mail/iva-mail.env.example "$IVA_RUNTIME_DATA_DIR/custom/plugins/iva-mail.env"
fi
chmod 600 "$IVA_RUNTIME_DATA_DIR/custom/plugins/iva-mail.env"
nano "$IVA_RUNTIME_DATA_DIR/custom/plugins/iva-mail.env"
```

Вместо `nano` можно использовать свой редактор. При стандартной конфигурации файл
лежит в `data/custom/plugins/iva-mail.env`; при `ASSISTANT_DATA_DIR` с другим значением
используйте вычисленный путь. Это **отдельный файл плагина**, почтовые доступы не нужно
добавлять в общую `.env`.

Заполните настройки своего провайдера. Пример для IMAP 993 и SMTP 465 с TLS:

```dotenv
MAIL_IMAP_HOST=imap.example.com
MAIL_IMAP_PORT=993
MAIL_IMAP_TLS=true
MAIL_IMAP_STARTTLS=false
MAIL_SMTP_HOST=smtp.example.com
MAIL_SMTP_PORT=465
MAIL_SMTP_TLS=true
MAIL_SMTP_STARTTLS=false
MAIL_SMTP_AUTH=login
MAIL_USERNAME=ceo@example.com
MAIL_PASSWORD=ПАРОЛЬ_ИЛИ_ПАРОЛЬ_ПРИЛОЖЕНИЯ
MAIL_FROM=CEO <ceo@example.com>
MAIL_ALLOW_SEND=false
```

Замените все примеры реальными значениями. Если провайдер требует SMTP 587 с
STARTTLS, задайте `MAIL_SMTP_PORT=587`, `MAIL_SMTP_TLS=false`,
`MAIL_SMTP_STARTTLS=true`. Режим аутентификации выбирайте по настройкам провайдера;
плагин поддерживает `login`, `plain` и `none`.

Установите и разрешите плагин:

```bash
npm run iva -- plugin add ./plugins/iva-mail
npm run iva -- plugin trust iva-mail
```

Если он уже установлен, вместо `add` используйте:

```bash
npm run iva -- plugin update iva-mail
```

Обновление берёт файлы из зарегистрированного источника. Команды управления
доверенными MCP-плагинами могут пересобрать и перезапустить Иву; выполняйте их
из терминала после окончания текущего разговора с агентом.

## 5. Установить Plaud-плагин

```bash
npm run iva -- plugin add ./plugins/iva-plaud
npm run iva -- plugin trust iva-plaud
npm run iva -- plugin list
```

Для уже установленного Plaud вместо `add`:

```bash
npm run iva -- plugin update iva-plaud
```

Оба плагина должны быть включены и доверены. Если какой-то ранее выключили:

```bash
npm run iva -- plugin enable iva-mail
npm run iva -- plugin enable iva-plaud
```

Plaud авторизуется через браузер; пароль и API-ключ в `.env` не нужны.

## 6. Поднять PostgreSQL и файловый архив

После настройки общей `.env` и установки плагинов:

```bash
npm run ingestion:setup
mkdir -p "$IVA_RUNTIME_DATA_DIR/plugin-data/iva-plaud/imports"
npm run ingestion:migrate
docker compose -p iva-agent --profile iva-data ps
```

Setup генерирует приватные доступы в `.env`, создаёт `data/garage/garage.toml`
и поднимает только `ceo-postgres` и `ceo-archive` проекта `iva-agent`. Он ждёт
готовности PostgreSQL. Стандартные loopback-порты — 55433 и 3900; другой PostgreSQL
на сервере не используется. Имена контейнеров и Compose-проект фиксированы:
для второй установки этого стека сначала нужно изменить их и порты.

Migration создаёт схему и переносит уже сохранённые локальные источники Plaud
с результатами разбора. Встречи из облака при этом не скачиваются. На чистой установке каталог
импортов создаётся командой `mkdir` выше, и migration переносит ноль источников.
Метаданные, очередь и почтовый курсор хранятся в PostgreSQL, прочитанные тексты
и разборы — в Garage S3. Аудио Plaud и файлы вложений пока не скачиваются.
Детали настройки и резервного копирования: [входящие и архив](../incoming-storage.md).

## 7. Собрать и запустить общее ядро

После изменения `.env`, схемы и установки плагинов:

```bash
npm run build
npm run iva -- restart
npm run iva -- status
```

Сборка должна завершиться успешно, агент и Telegram bridge — работать.
Плагины запускаются через свои MCP-прокси, а фоновые проверки почты и Plaud пока выключены на новой установке.

Напишите своему Telegram-боту:

> Привет. Покажи мои активные проекты и обязательства.

Ожидается ответ Ивы. Пустая память на новой установке допустима. Если бот молчит,
сначала проверьте allowlist и работу bridge, прежде чем переходить к интеграциям.

## 8. Проверить почту и при необходимости разрешить отправку

В Telegram попросите:

> Загрузи mail-скилл и проверь подключение через mail_check_connection.
> Не читай и не отправляй письма при этой проверке.

`mail_check_connection` проверяет реальные входы IMAP и SMTP.
`mail_connection_status` показывает только наличие настроек, поэтому его успеха
недостаточно. Затем проверьте чтение:

> Покажи темы последних пяти входящих. Не помечай письма прочитанными.

После успешной проверки можно оставить `MAIL_ALLOW_SEND=false` для чтения и
подготовки сообщений. Если нужна отправка, измените его на `true` в `iva-mail.env`
и перезапустите почтовый MCP-прокси, чтобы он загрузил новые настройки. Для стандартных
systemd user services:

```bash
systemctl --user restart iva-mcp-iva-mail-mail.service
```

Принцип проверки отправки: попросите подготовить письмо на свой адрес, проверьте
точный preview с адресатами, темой и текстом и только отдельным следующим сообщением
подтвердите отправку. Само включение `MAIL_ALLOW_SEND=true` не отменяет этот порядок.

Если хотите сохранять отправленную копию через IMAP, сначала попросите список папок
через `mail_list_mailboxes`, затем задайте точное имя в `MAIL_SENT_MAILBOX` и
перезапустите почтовый прокси. Не угадывайте имя локализованной папки «Отправленные».

## 9. Авторизовать Plaud и запустить импорт встреч

В Plaud включите Cloud Sync и дождитесь готовности транскрипта тестовой записи.
В новом разговоре с Ивой напишите:

> Подключи мой аккаунт Plaud. Запусти вход в Plaud.

Пройдите авторизацию в браузере под нужным аккаунтом CEO.
На сервере без браузера предварительно откройте туннель **на своём компьютере**:

```bash
ssh -L 8199:127.0.0.1:8199 user@server
```

Замените SSH-адрес своим, держите туннель открытым и откройте полученную от Ивы
ссылку авторизации на этом компьютере. После входа попросите показать последние
записи и проверьте, что это правильный аккаунт.

На сервере включите фоновый импорт и выполните первый запуск:

```bash
npm run plaud:sync -- --enable
```

При первом включении фиксируется `plaudSync.since`: импортируются только встречи,
записанные с этого момента. При повторном включении сохранённая граница остаётся.
Запишите новую тестовую встречу после включения, включите Cloud Sync и дождитесь
готовности транскрипта. Команда передаёт до пяти ожидающих источников на разбор агенту. Смотрите счётчики `checked`, `imported`, `pending`, `errors`.
`pending` выводится до разбора. При наличии работы успешный разбор заканчивается
строкой `Plaud context-processing turn finished`.

Проверка в чате:

> Что решили на встрече «Название»? К каким проектам и людям она относится,
> кто что обещал и какие шаги нужны мне? Покажи источники и неясности.

Дальше расписание проверяет записи каждые 10 минут при работающем агенте.
Старые встречи и старый необработанный архив исключаются границей `plaudSync.since`.
Первый запуск без новых встреч может завершиться с `imported 0`, это нормально.
Подробнее: [запуск и диагностика Plaud](plaud.md).

## 10. Поднять LibreChat и создать аккаунты

Ива уже работает как сервис. На той же машине из рабочего каталога проекта:

```bash
docker --version
docker compose version
docker compose --profile librechat up -d --build librechat
docker compose --profile librechat ps
```

Ожидаются работающие `librechat` и `librechat-mongodb`, у MongoDB — healthy.
Контейнер LibreChat обращается к работающей Иве по `127.0.0.1:${IVA_PORT}/v1`.

Создайте аккаунты, подставив **те же реальные email**, которые использовали выше:

```bash
npm run librechat:accounts -- admin@example.com ceo@example.com
npm run librechat:accounts -- --check admin@example.com ceo@example.com
```

Скрипт интерактивно попросит данные недостающих аккаунтов и пароли. Саморегистрация
через браузер выключена. Если уже есть другие аккаунты, скрипт откажется менять
состав пользователей: сначала разберите их отдельно, он не удаляет пользователей.

Текущая схема создаёт **оба аккаунта с ролью ADMIN** в LibreChat. Они используют
один vault Ивы; роли и аккаунты LibreChat не разделяют память CEO и администратора.

На своём компьютере откройте туннель:

```bash
ssh -L 3080:127.0.0.1:3080 user@server
```

Откройте `http://127.0.0.1:3080`, войдите аккаунтом CEO и выберите endpoint `Iva`,
модель `iva`. При другом `LIBRECHAT_PORT` измените оба порта туннеля и адрес браузера.
В LibreChat не нужно повторно добавлять провайдера модели, Mail MCP или Plaud MCP:
они уже находятся в Иве.

Проверьте текстовый ответ, список проектов и чтение почты. Затем задайте вопрос о
той же импортированной встрече: браузерный чат должен видеть общую память Ивы.

Для микрофона нужен Deepgram и совпадение адреса STT в `librechat.yaml` с реальным
`IVA_PORT`: проверьте `speech.stt.allowedAddresses` и
`speech.stt.openai.url`, они заданы отдельно от основного endpoint. При изменении
конфигурации пересоздайте LibreChat. Подробнее: [LibreChat](../librechat.md).

## 11. Включить новые входящие почты и проверить уведомления

После запуска LibreChat и настройки `LIBRECHAT_PUBLIC_URL`:

```bash
npm run mail:sync -- --enable
```

Первый успешный запуск фиксирует текущий почтовый UID; существующие письма не
импортируются. Дальше INBOX проверяется каждые 10 минут, со смещением на 5 минут
от Plaud. При новой версии почтового ящика (UIDVALIDITY) фиксируется новая граница.
В установленном плагине должен быть инструмент `mail_poll_messages`.

Пришлите новое письмо в подключённый ящик после первого успешного запуска.
Можно дождаться расписания или проверить сразу:

```bash
npm run mail:sync
```

Ива сохраняет прочитанный текст в архив, готовит разбор и создаёт обычный чат
в проекте Libre **«Входящие Ивы»**. Обсуждение идёт в стандартном окне чата.
Telegram получает уведомление с кнопками **«Открыть в Libre»** и **«Показать тут»**.
Письмо остаётся непрочитанным. Ошибка не двигает курсор мимо несохранённого письма;
ошибка разбора одного источника не останавливает остальные, повторы не создают
дубликат отчёта. Фоновая модель не получает инструменты и не отправляет ответы.
Письма пока не записываются автоматически в vault; при разборе используется поиск
уже существующей памяти. Вложения видны только по метаданным.

Числа `imported`, `processed`, `pending`, `errors` выводятся без текста писем.
При отсутствии новых писем нули означают успешную проверку.

В LibreChat войдите разрешённым в `LIBRECHAT_NOTIFICATION_USERS` аккаунтом.
На сервере создайте одно проверочное уведомление:

```bash
npm run iva -- notify "Проверка запуска Ивы: Telegram и LibreChat подключены"
```

Ожидается одно событие в колокольчике LibreChat и сообщение в
`TELEGRAM_NOTIFICATION_CHAT_ID`, если Telegram настроен. Колокольчик опрашивает
хранилище примерно каждые 15 секунд. Не создавайте отдельное расписание в LibreChat
для тех же задач: напоминания и фоновые задания выполняет Ива.

Теперь запуск проверен, если:

- Агент и Telegram bridge работают, бот отвечает только разрешённым пользователям.
- CEO входит в LibreChat и получает ответы от endpoint `Iva`.
- В обоих каналах доступны одни проекты, контакты и обязательства.
- Mail проходит реальную проверку IMAP/SMTP и читает входящие; отправка настроена
  согласно выбранному режиму и требует подтверждения подготовленного письма.
- Plaud показывает записи нужного аккаунта, первый транскрипт импортирован, карточка
  встречи и результат разбора доступны в памяти.
- Новое тестовое письмо разобрано в чате «Входящих Ивы»; Telegram показывает
  уведомление и две кнопки. Обычное проверочное уведомление видно в колокольчике.
- PostgreSQL и Garage работают; оба фоновых задания завершаются с кодом 0.

Утренний дайджест и ночные отчёты — отдельные настройки, по умолчанию выключены.
Их можно включить через `/menu → Notices`; это не влияет на работу памяти или
отдельно включённые проверки Plaud и почты.

## Где хранится состояние

Пути ниже — стандартные; учитывайте свои `ASSISTANT_DATA_DIR`, `ASSISTANT_VAULT_DIR`
и каталоги карточек из схемы.

| Что                                                       | Где                                                                                                  |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Провайдер, Telegram, ключ API LibreChat и общие настройки | `.env`                                                                                               |
| CEO-память, проекты, люди, встречи и обязательства        | `vault/`                                                                                             |
| Настройки IMAP/SMTP                                       | `data/custom/plugins/iva-mail.env`                                                                   |
| Состояние установленных плагинов                          | `data/custom/plugins.json`                                                                           |
| Приватные данные Mail и Plaud                             | `data/plugin-data/iva-mail/`, `data/plugin-data/iva-plaud/`                                          |
| Архив источников Plaud и результатов разбора              | `data/plugin-data/iva-plaud/imports/`                                                                |
| Переключатели фоновых функций                             | `data/settings.json`                                                                                 |
| Последний результат фонового импорта Plaud                | `data/plaud-sync-status.json`                                                                        |
| Очередь, метаданные и курсор почты                        | PostgreSQL, схема `iva_ingestion`, volume `iva-agent_ceo-postgres`                                   |
| Архив текстов и разборов                                  | Garage S3, bucket `iva-archive`, volumes `iva-agent_ceo-archive-meta` и `iva-agent_ceo-archive-data` |
| Приватная конфигурация архива                             | `.env` и `data/garage/garage.toml`                                                                   |
| Последний результат проверки почты                        | `data/mail-sync-status.json`                                                                         |
| Общий inbox уведомлений                                   | `data/notifications.json`                                                                            |
| Аккаунты и истории LibreChat                              | Docker volumes, включая `librechat-mongodb`                                                          |

Для восстановления нужны приватные бэкапы vault, каталога данных, конфигурации
и Docker volumes LibreChat, а также дамп PostgreSQL и согласованный снимок
двух volumes Garage. См. [сохранность архива](../incoming-storage.md#сохранность). Не ограничивайтесь копированием репозитория с кодом.

## Повторный запуск и диагностика

Для действующей CEO-установки используйте [точные команды её сервисов](ceo-operations.md).
Таблица ниже относится к стандартной одиночной установке.

| Задача или симптом                                 | Действие                                                                                                                                          |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Состояние агента и Telegram                        | `npm run iva -- status`                                                                                                                           |
| Логи агента                                        | `npm run iva -- logs`                                                                                                                             |
| Логи Telegram bridge                               | `npm run iva -- logs poll`                                                                                                                        |
| Состояние плагинов                                 | `npm run iva -- plugin list`                                                                                                                      |
| Перезапуск ядра после изменения общей `.env`       | `npm run iva -- restart`                                                                                                                          |
| Новые инструменты или скиллы ядра не появились     | `npm run build`, затем перезапуск                                                                                                                 |
| Почта не подключается после изменения её env-файла | Перезапустите Mail MCP-прокси, повторите `mail_check_connection`; проверьте пароль приложения и TLS                                               |
| LibreChat не получает ответы или возвращает 401    | Проверьте агент, `IVA_PORT`, одинаковый `OPEN_WEBUI_API_KEY` у Ивы и LibreChat; после изменения `.env` перезапустите Иву и пересоздайте контейнер |
| Колокольчик не открывается                         | Проверьте email в `LIBRECHAT_NOTIFICATION_USERS` и совпадение `LIBRECHAT_NOTIFICATION_SECRET` в двух процессах                                    |
| Состояние и логи LibreChat                         | `docker compose --profile librechat ps`; `docker compose --profile librechat logs --tail=100 librechat`                                           |
| Ручной импорт Plaud                                | `npm run plaud:sync`                                                                                                                              |
| Остановить последующие фоновые импорты Plaud       | `npm run plaud:sync -- --disable`; архив остаётся                                                                                                 |
| Проверить почту вручную                            | `npm run mail:sync`; старые письма не загружаются                                                                                                 |
| Остановить фоновые проверки почты                  | `npm run mail:sync -- --disable`; архив и курсор сохраняются                                                                                      |
| Состояние PostgreSQL и Garage                      | `docker compose -p iva-agent --profile iva-data ps`                                                                                               |
| Статус проверок входящих                           | `cat data/mail-sync-status.json data/plaud-sync-status.json`                                                                                      |
| Остановить только браузерный интерфейс             | `docker compose --profile librechat stop librechat librechat-mongodb`                                                                             |
| Остановить агент и Telegram bridge                 | `npm run iva -- stop`; MCP-прокси плагинов управляются отдельно через `plugin untrust`/`disable`                                                  |

Для применения изменённой `.env` к LibreChat:

```bash
docker compose --profile librechat up -d --build --force-recreate librechat
```

Не удаляйте Docker volumes при обычном перезапуске: они содержат аккаунты и историю.
Команды `logs` следуют за журналом; выход — `Ctrl+C`.

Telegram-бот из этой инструкции отличается от личного Telegram userbot. Доступ к
переписке личного аккаунта не нужен для работы бота и настраивается отдельно, если
CEO хочет такой сценарий; [описание возможностей](use-cases.md).
