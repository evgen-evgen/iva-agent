# Полный запуск Plaud → память CEO

Полный запуск всей Ивы, включая Telegram, Mail и LibreChat:
[единая инструкция](full-startup.md).

Этот сценарий подключает аккаунт Plaud к Иве, включает фоновый импорт и запускает
разбор встреч в контексте проектов и людей. После обработки Ива сохраняет карточку
встречи, связывает её с существующей памятью и выделяет решения, явные обязательства
и рекомендуемые шаги CEO. Исходные транскрипты и саммари хранятся отдельно.

Интеграция работает через официальный Plaud MCP. Zapier для этого запуска не нужен.

## 1. Подготовить установку

Если Ива ещё не установлена, сначала пройдите [установку](install.md) и убедитесь,
что она отвечает в чате. Для этого сценария нужен работающий провайдер модели:
получение записей выполняет MCP, а разбор встреч — модель Ивы.

Дальнейшие команды выполняйте на машине Ивы из корня checkout, в котором находятся
`.env`, `package.json` и `plugins/iva-plaud/`. В исходниках должны быть
`scripts/plaud-sync.ts` и `agent/tools/plaud_import.ts`. Инструкция рассчитана на код
с этой интеграцией; наличие установленного MCP-плагина само по себе не добавляет
фоновый импорт в старую версию ядра.

В примерах CLI вызывается через `npm run iva --`, чтобы команды относились к этой
установке, даже если на машине есть другие экземпляры Ивы. Node.js должен быть
версии 24; зависимости проекта должны быть установлены.

## 2. Включить CEO-профиль

В `.env` установите или обновите существующие значения:

```dotenv
IVA_MEMORY_PROFILE=ceo
IVA_CEO_NAME=Имя CEO
```

`IVA_CEO_NAME` необязателен. Используйте имя, которым владелец обозначен в памяти,
чтобы Ива отдельно показывала его обязательства в оперативном контексте и дайджесте.
Не создавайте повторные строки для уже заданных переменных.

Затем примените схему к vault:

```bash
npm run init-vault
```

Ожидаемый результат — сообщение `CEO profile applied` или `CEO profile already present`.
Миграция добавляет типы `meeting` и `commitment` и их каталоги, сохраняя существующие
карточки. Её можно выполнить повторно. Каталог памяти берётся из
`ASSISTANT_VAULT_DIR`, по умолчанию `vault/`.

## 3. Установить и разрешить Plaud-плагин

```bash
npm run iva -- plugin add ./plugins/iva-plaud
npm run iva -- plugin trust iva-plaud
npm run iva -- plugin list
```

Установленный плагин должен быть включён и доверен: только тогда запускается его
локальный MCP-прокси. Если плагин ранее выключали, включите его:

```bash
npm run iva -- plugin enable iva-plaud
```

Установка копирует плагин в каталог данных. Если он уже установлен, команда `add`
предложит обновление вместо повторной установки:

```bash
npm run iva -- plugin update iva-plaud
```

Обновление берёт файлы из ранее зарегистрированного источника. Для локального
плагина это исходная папка: в ней должен быть актуальный скилл. Данные и авторизация
находятся отдельно от установленной копии. Команды управления доверенным MCP-плагином
могут сами выполнять сборку и перезапуск; запускайте их из терминала.

## 4. Собрать и перезапустить Иву

```bash
npm run build
npm run iva -- restart
npm run iva -- status
```

Сборка должна завершиться успешно, а сервис агента — работать. Перезапуск нужен,
чтобы агент загрузил новый инструмент `plaud_import`, скилл `plaud-process`,
расписание `plaud-sync` и CEO-схему. Само расписание ещё выключено.

Выполняйте перезапуск из терминала после завершения текущего разговора с Ивой.
Для установки, которую вы запускаете вручную без systemd, перезапустите её обычным
способом; `iva restart` относится к управляемым сервисам.

## 5. Авторизовать аккаунт Plaud

В Plaud включите Cloud Sync. Подготовьте хотя бы одну запись с готовым транскриптом.

Откройте новый разговор с Ивой и напишите:

> Подключи мой аккаунт Plaud. Запусти вход в Plaud.

Пройдите авторизацию в браузере под аккаунтом CEO и разрешите доступ. Пароль Plaud
и API-ключ не нужно записывать в `.env`.

Если Ива работает на сервере без браузера, перед началом входа откройте на своём
компьютере SSH-туннель и оставьте его работающим до завершения авторизации:

```bash
ssh -L 8199:127.0.0.1:8199 user@server
```

Замените `user@server` своим SSH-адресом. Откройте ссылку, которую вернёт Ива,
в браузере на этом компьютере: callback на порт `8199` через туннель попадёт на сервер.

Проверьте подключение в чате:

> Покажи последние записи из моего Plaud.

Ожидаемый результат — список записей правильного аккаунта. Если аккаунт пустой,
сначала синхронизируйте запись с облаком Plaud и дождитесь готовности транскрипта.

## 6. Выполнить первый импорт и включить фоновые проверки

Из корня установки:

```bash
npm run plaud:sync -- --enable
```

Команда проверит CEO-схему, включит `plaudSync.enabled` в настройках, получит записи
и передаст до пяти ожидающих источников на разбор работающему агенту.

В выводе появятся счётчики:

```text
Plaud: checked ..., imported ..., pending ..., errors ...
Plaud context-processing turn finished
```

`pending` показывается **до** разбора: ненулевое значение в этой строке не означает
ошибку. Если очередь больше пяти источников, следующие запуски продолжат обработку.
При пустом аккаунте или отсутствии готовых транскриптов импорт может завершиться
со счётчиком `imported 0`, без строки о разборе.

Вместо CLI можно попросить Иву:

> Включи автоматическую синхронизацию Plaud и выполни первый импорт с разбором встреч.

Инструмент включения в чате меняет настройку; первый импорт и разбор — отдельные
действия в этом запросе. Новая сборка и работающий агент нужны в обоих вариантах.

## 7. Проверить результат

Попросите Иву разобрать конкретную встречу:

> Что решили на встрече «Название»? С какими проектами и людьми она связана,
> кто что обещал и какие шаги нужны от меня? Покажи источники и неясности.

Проверьте, что ответ различает факты встречи, обязательства участников и рекомендации.
Неоднозначного участника или срок Ива должна оставить вопросом, а не придумывать.
Обязательство сохраняется, когда из источника известны владелец, результат и срок.

При стандартных путях результат хранится здесь:

| Данные                           | Расположение                                   |
| -------------------------------- | ---------------------------------------------- |
| Карточки встреч                  | `vault/cards/meetings/`                        |
| Явные обязательства              | `vault/cards/commitments/`                     |
| Исходники и версии               | `data/plugin-data/iva-plaud/imports/<key>/`    |
| Текущий исходник                 | `current.json` внутри каталога записи          |
| Сохранённая версия исходника     | `<revision>.json`                              |
| Результат разбора версии         | `<revision>.analysis.json`                     |
| Отметка завершённого разбора     | `processed.json`                               |
| Курсор проверки архива и очереди | `data/plugin-data/iva-plaud/imports/scan.json` |
| Статус фонового задания          | `data/plaud-sync-status.json`                  |

`<key>` зависит от аккаунта и ID записи; имя записи в Plaud можно менять без создания
новой встречи. Отдельные исходники не копируются целиком в карточки или дневной лог.
Если `current.json` есть, а соответствующая версия ещё не отмечена в `processed.json`,
источник ожидает разбора. Не редактируйте эти отметки вручную: они управляют повторами.

Пути `data/` и `vault/` в таблице — значения по умолчанию. Учитывайте свои
`ASSISTANT_DATA_DIR`, `ASSISTANT_VAULT_DIR` и настроенные в схеме каталоги карточек.
Архив содержит полные тексты встреч, поэтому включайте его в приватные бэкапы вместе
с каталогом данных. Аудио импортёр не скачивает.

## Как работает фон после запуска

Пока агент работает и синхронизация включена, расписание срабатывает каждые 10 минут.
Каждый запуск проверяет первую страницу записей и одну очередную страницу архива,
затем разбирает до пяти ожидающих источников. Поэтому первый запуск не означает,
что весь исторический архив уже импортирован.

Старые записи перепроверяются по очереди, чтобы обнаруживать изменения содержимого.
Повторное чтение неизменённой записи не создаёт новую версию. Изменение транскрипта,
саммари или сохраняемых метаданных создаёт версию и возвращает источник на разбор.
Исправления владельца и более новые факты в памяти нужно сохранять; конфликт с
обновлённым источником выносится на проверку.

Задание оставляет неразобранные источники в очереди и повторяет попытки позже.
Очередь обработки вращается, чтобы ошибка одной встречи не блокировала остальные.
Импорт не отправляет отдельные сообщения или уведомления CEO: результат доступен
в памяти и по запросу в чате. Если агент выключен, фоновые проверки не выполняются.

## Ручной запуск, остановка и повторное включение

Однократный импорт и разбор:

```bash
npm run plaud:sync
```

Он работает и при выключенной фоновой синхронизации. Для вопросов о свежих встречах
Ива также может синхронизировать данные инструментом; такая проверка охватывает
первые две страницы, а исторический архив продолжает обходить фоновое задание.

Выключить следующие фоновые запуски:

```bash
npm run plaud:sync -- --disable
```

Это не удаляет архив и карточки и не прерывает уже выполняющееся задание.
Чтобы включить синхронизацию снова, выполните команду с `--enable`.

## Если запуск не удался

| Симптом                                                              | Что проверить и сделать                                                                                                                                                  |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Missing script: plaud:sync`, неизвестный `plaud_import` или скилл   | Команды выполняются из нужного checkout; в нём есть код интеграции. Повторите сборку и перезапуск агента.                                                                |
| Ошибка о необходимости CEO-схемы                                     | Проверьте `IVA_MEMORY_PROFILE=ceo` и `ASSISTANT_VAULT_DIR` в `.env`, выполните `npm run init-vault`, перезапустите агент.                                                |
| `Install and trust iva-plaud before synchronizing`                   | Проверьте `plugin list`, включите плагин и разрешите его через `plugin trust`.                                                                                           |
| `fetch failed` или отсутствует токен MCP-прокси                      | Убедитесь, что локальный прокси плагина запущен; проверьте состояние плагина и повторите `plugin trust`. Это ещё не доказательство ошибки аккаунта Plaud.                |
| `Plaud MCP call failed`                                              | Проверьте доступ к аккаунту через список записей в чате. При ошибке авторизации повторите вход; также проверьте доступ сервера к Plaud.                                  |
| После записи `imported 0`                                            | Проверьте Cloud Sync, правильный аккаунт и наличие готового транскрипта. Неизменённые уже импортированные записи также дают `imported 0`.                                |
| `errors` больше нуля                                                 | Часть записей не удалось полностью прочитать. Исправьте подключение и повторите ручной запуск; старые записи будут перепроверены при обходе архива.                      |
| `context processing failed` или выбранные источники остались pending | Проверьте работающий агент, доступ к провайдеру модели и возможность записи в vault; исходники уже сохранены, повторный запуск продолжит разбор.                         |
| Ручной запуск работает, а фон не появляется                          | Проверьте включение синхронизации, успешную сборку, перезапуск и работающий сервис агента. Посмотрите `plaud-sync-status.json` после следующего десятиминутного запуска. |

Логи агента доступны через `npm run iva -- logs`; команда следует за журналом,
выход — `Ctrl+C`. Успешный ручной импорт сам по себе не обновляет файл статуса
фонового задания: тот записывает запуск по расписанию.

Команда `--enable` сохраняет настройку до попытки подключения к Plaud. Если первый
импорт завершился ошибкой, фон останется включённым и будет повторять попытки;
на время исправления его можно выключить командой `--disable`.
